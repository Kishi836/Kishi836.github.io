Parakaya

Rust, custom instruction set, in active development +

Problem

Make a running program hop between a PC, a Raspberry Pi, a phone and a cloud VM mid-execution, across CPU architectures, and survive power loss at any instant.

Approach

The VM core is a Rust workspace: a compact instruction set, tagged values, and execution state built to checkpoint on one architecture and resume on another. Designed spec-first, with decision records for every architectural call.

Result

In active development, so there are no results to claim yet. The instruction set below is from the current VM core.

Supply-Chain Trust Gate

Capstone, team of four, PES University. I own the PyPI adapter +

Problem

Build pipelines and AI coding assistants act on what a vulnerability database says, such as "fixed in version X", without checking it against what was actually shipped. When GitHub and PyPA disagree, someone acts on a wrong record.

Approach

Fingerprint the advisory's fix commit, download every PyPI release of the package, and find the first release that really contains the fix. A trust router then answers TRUST, VERIFY, FLAG or ABSTAIN, with the evidence, before anything is installed.

Result

Stage 0, written down before we counted: 820 real cases where GitHub and PyPA name different fixed versions (pass mark 300), 711 with a fix commit we can trace. Phase I runs to November 2026.

PassGen Vault

Single-file web app and native Android client +

Problem

One password vault shared by a laptop and an Android phone, without trusting any server with the plaintext.

Approach

One AES-256-GCM vault stored in OneDrive, opened by a single-file web app and a native Android client. Keys come from PBKDF2 at 600,000 iterations, and fingerprint unlock is backed by hardware keys.

Result

A working zero-knowledge password manager. Its generator is built on a CSPRNG with rejection sampling, so there is no modulo bias.

Repo6uard

Team of six, CIE Ignite startup program at PES +

Problem

Pattern-based scanners flag code without context and say nothing about vulnerable dependencies.

Approach

A hybrid scanner: static analysis finds known patterns, an LLM reasoning pass validates them in context and writes fix suggestions, and dependencies get cross-checked against Google's OSV and the NVD.

Result

The working prototype scanned a deliberately vulnerable repo and reported 15 issues across 8 OWASP categories in under 30 seconds. We pitched it through two phases of the campus startup program and missed the final round by one position. The scanner still works.
